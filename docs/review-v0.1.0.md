# Pre-release review of v0.1.0 — 2026-10-19

Scope: security boundaries, historical-data leakage and reproducible packaging. Findings below refer to the initial local commit `a647269`; all listed defects are corrected in the reviewed local release. No public push or hosted publication was performed.

| Priority | Finding and consequence | Correction | Reproduction/regression |
| --- | --- | --- | --- |
| P1 | `--force` opened existing files with `w`; a hard-linked output truncated an unrelated target | Sibling temporary file + fsync + atomic directory-entry replacement; failure preserves prior report | `test_force_does_not_modify_hardlink_target`, `test_failed_replacement_preserves_existing_report` |
| P1 | Git status executed a repository clean filter while hashing a tracked file | Reject local filter/diff/submodule config before starting Git; disable external attributes/excludes and submodule summaries | `test_git_status_must_not_run_clean_filter` created a real marker on the old version and no marker after the fix |
| P1 | Test labels determined probability eligibility, making the reported test no longer independent of model selection | Add an earlier selection block; final test cannot change eligibility, weights or model identity | `test_holdout_labels_do_not_select_model`, `test_single_class_test_labels_do_not_change_eligibility` |
| P1 | `--as-of` used completion time, including delayed labels that were unavailable at forecast time | Require/validate outcome availability; filter and block boundaries use `outcome_recorded_at` | `test_delayed_outcome_excluded_at_as_of`, `test_delayed_training_outcome_blocks_fit` |
| P1 | Plan snapshots had no enforceable pre-execution timestamp and known task groups could cross splits | Require plan provenance for probability mode; reject late snapshots; isolate complete optional group IDs | `test_post_execution_plan_snapshot_rejected`, `test_missing_provenance_withholds_probability`, group overlap/incomplete-group cases |
| P1 | Assignment redaction consumed only `Bearer`, exposing the credential; prefixed secret names were also missed | Redact full auth value first; recognize prefixed/quoted assignments | Auth header, prefixed environment assignment and embedded JSON secret cases |
| P2 | Windows Git discovery could consider implicit CWD/relative executables; metadata walk errors could be silently skipped | Resolve explicit absolute trusted PATH entries only; fail closed on metadata traversal errors and skip cyclic lookup paths | Git lookup, metadata-walk and link-cycle cases |
| P2 | Duplicate JSON keys and nonfinite constants made input interpretation ambiguous | Strict JSON parser rejects both for CLI inputs and JSON project config | Duplicate-key and nonfinite-input cases |
| P2 | Source tarball omitted `docs/test-results.txt`; CI only exercised source imports and did not verify installation round trips | Include text evidence; add portable distribution verifier and CI step | Real sdist rebuild, byte comparison, complete-manifest checks and fresh offline installation |

The review adds **24 cases** to the original 84 for **108 passing tests** on Windows/Python 3.12, with zero failures/errors/skips. Archive traversal/link rejection and timestamp overflow are additionally tested. Real hard-link reproduction required the Windows context outside the restrictive tool sandbox; all test files remained in temporary workspace directories.

Release verification runs the installed engine outside the source tree, without PYTHONPATH, using 17 CLI invocations; a separate 16-call example pass regenerates reports and validates six JSON documents. The distribution verifier safely extracts only regular source members and rejects traversal/link entries before building this project's own trusted source. It is a maintainer command, not an inspection-engine feature.

Release-readiness follow-up adds ten cases for a total of **120 passing tests**, plus severity-policy exit codes, finite-exponent validation, bounded declarations, legacy Windows reparse detection, documented official Skill directories and a matrix-gated manual publication workflow. Distribution acceptance now includes 18 installed CLI invocations; report generation remains a separate 16-call pass.

The first actual remote matrix additionally found macOS temporary-directory aliasing in CLI test fixtures and an old preinstalled setuptools retained for Windows 3.10/3.11 no-isolation builds. Fixtures now canonicalize their explicit workspace paths without weakening output-link rejection. CI pins the required backend minimum and two additional regressions validate old-backend rejection and supported-backend acceptance. Final-test provenance is unchanged. Publication was correctly skipped by the failed first matrix.

Residual limits: timestamps/group IDs are unauthenticated declarations; undisclosed correlations and distribution shift remain possible; no production-history accuracy claim is justified. The scanner assumes a stable filesystem and trusted system Python/Git/PATH; conservative Git rejection leaves some repositories unverified. Linux/macOS and other Python versions remain CI targets, not locally verified results. Release publication remains gated on the actual remote matrix; local release assets and tags are separately verified.
