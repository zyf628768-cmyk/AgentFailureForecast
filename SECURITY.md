# Security policy

Default operation is local, offline and read-only. No plan command, project script, import hook, deployment, migration, deletion or paid API is executed. The sole inspection subprocess is installed system Git with shell disabled, optional locks disabled, hooks/fsmonitor disabled, sanitized Git environment and a timeout. Git lookup only considers absolute PATH entries, excluding the working directory and inspected root; Windows implicit CWD executable lookup is not used. PATH and the Python installation must themselves be trusted.

Explicit CLI plan/history/report paths are user-selected local inputs, outside root if desired. Project-relative prerequisite/configuration paths must remain inside root and may not contain links or traversal. Input size and step count are bounded. Git failures become findings, not proof of cleanliness. Git metadata is checked for links (at most 10000 entries) before Git runs. Worktree metadata files, commondir, object alternates, local config includes and core.worktree overrides are conservatively rejected to prevent external metadata reads. Git submodules/worktrees therefore receive an unverified Git status rather than full support. The explicitly selected root is trusted for that single Git status command using an exact `safe.directory` override; global Git configuration is never changed.

Git status can invoke clean/process filters, so local `[filter]`, `[diff]` and `[submodule]` config sections are rejected before invoking Git. Submodule repositories are reported as unsupported instead of claiming cleanliness. External attributes/excludes files and submodule summaries are disabled; metadata traversal errors fail closed. These conservative restrictions intentionally leave some repositories unverified.

This tool does not recursively scrape sources or print variable values. Reports omit raw plans and Git filenames and apply defense-in-depth redaction for common secrets, including full Bearer/Basic authorization values and prefixed secret assignments. Redaction of arbitrary user-supplied report text is best effort; manually inspect reports before publication. HTML escapes all content. Never treat a report as executable instructions. No renderer fetches remote resources.

Reports require explicit `--output`. Without `--force`, exclusive creation prevents overwriting. With `--force`, a new sibling temporary file is flushed and atomically replaces the directory entry; existing hard-link targets are never truncated. Replacement failure leaves the existing report intact and cleans the temporary file. Symlink/junction destinations and parents are rejected. Concurrent parent-directory replacement remains outside the stable-filesystem assumption.

Path checks reduce accidental boundary crossing but cannot defeat hostile concurrent filesystem changes (TOCTOU), OS administrator compromise or malicious system executables. Inspect a stable snapshot with trusted local tools for adversarial repositories. Permissions and credentials are checked locally only; live remote capability is deliberately not tested. Regex signals can miss obfuscated commands and non-English formulations.

Windows reparse points/junctions are rejected using file attributes, including on Python versions without `Path.is_junction`. JSON numeric overflow and excessive prerequisite/dependency declarations are rejected before analysis. The release workflow is manually dispatched and waits for the complete OS/Python test and installation matrix; publishing permission is limited to its final job. Runtime scanning never publishes anything.

Report suspected vulnerabilities privately to the repository maintainer through GitHub private vulnerability reporting once enabled; do not include live secrets in public issues. No hosted reporting endpoint is bundled.
